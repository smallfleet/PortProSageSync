PortProSage Sync — User Guide

The complete, walk-through reference for the PortProSage Admin application — the tool RS Rush Transfer Xpress Inc. uses to sync PortPro invoices into Sage 50 (Canadian Edition).

If the blue "?" help icon next to a field doesn't answer your question, this guide should. Open it any time from inside the app: click Help in the top bar. Looking for the technical/developer documentation instead (architecture, file formats, how the Windows Service itself works)? See README.md in the same folder as this file.

1. What this app actually does

The Admin app itself never talks to PortPro or Sage 50 directly. All it does is:

  1. Read and edit two settings files (appsettings.json and appsettings.Local.json) that live in the Service folder.
  2. When you click a Run/Start button, either launch PortProSage.Service.exe (the program that actually does the work) or drop a small request file for an already-running one to pick up.

So editing a field and NOT clicking that tab's Save button does nothing — and clicking Save does not, by itself, run anything either. The two actions are separate on purpose: you can change settings any time without accidentally kicking off a sync.

Every field in the app has a small circular blue "?" icon next to it — click it for a plain-language explanation and a worked example, right where you're looking. This guide covers the same ground in more depth, plus how the tabs work together.

At the very bottom of the window is a status bar that shows something like Source: appsettings.json → Sync:PollingIntervalMinutes whenever you click into a field — so you always know exactly which file, and which setting inside it, you're editing.

2. Before you start: two processes, one Sage 50 seat

There are two distinct ways to run a sync, and they are mutually exclusive — you can only ever have one active at a time:

Manual RunAutomatic Sync
You start it fromManual Run tabAutomatic Sync tab
What actually launchesA one-shot process that runs once and exitsA long-running process that keeps polling
You chooseExactly which invoices to process (by date, range, list, or "continue")Nothing per-run — it always continues from the watermark
Runs untilIt finishes (usually seconds to a few minutes)You click Stop, or the machine restarts

Why they can't run together: both would try to open the same Sage 50 company file under the same Sage 50 username at the same time. Sage 50 rejects a second simultaneous session under one username — so the app disables whichever button would create a conflict, and the top bar's Process: status line always tells you which one (if either) is currently active.

If you need to run something manually while the Automatic Service is on, stop the Automatic Service first (top bar Stop button, or the Stop button on the Automatic Sync tab), do your manual run, then start it again.

3. The top bar

Visible above every tab, at all times:

  • Service folder — the folder containing appsettings.json, appsettings.Local.json, and PortProSage.Service.exe. The app guesses this on first launch and remembers whatever you last pointed it at.
    • Browse... — pick a different folder (a full folder picker dialog).
    • Reload — re-read settings from whatever folder is currently typed in the box, without opening the picker. Use this if you edited the settings files by hand outside the app.
  • Help — opens this User Guide in your default browser.
  • v2.12.25 (top-right, gray) — the exact build number of the Admin app you're currently running. Useful when confirming "did the new build actually install" — compare this against what you were told to expect.
  • Process: — always shows the real, current state:
    • Not running (red) — nothing is active; either button is free to use.
    • Automatic Service running - PID 1234, since 9:03 AM (green).
    • Manual Run running - PID 5678, since 9:15 AM (orange).
    • A small spinning progress bar appears next to this label whenever anything is active.
  • Stop (top bar) — stops whichever process is currently running, without needing to switch to the tab that started it. Confirms first.

4. Manual Run tab

Use this to run a sync exactly once, right now, with full control over exactly which invoices get processed.

Mode dropdown — the five ways to pick invoices

ModeSelects invoices byWhen to use it
Invoice date (default)The invoice's own PortPro billing date, within your From/To windowThe safe default for "process everything invoiced in this window." Can't accidentally pull in something merely edited recently that's actually dated long ago.
ContinueThe saved watermark — automatically resumes right after the last invoice this app successfully processedRoutine day-to-day catch-up runs. No dates or numbers to fill in at all.
Last changed datePortPro's "last updated" timestamp, within your From/To windowChasing "what changed recently" specifically. Caution: can pull in an invoice dated well outside your window if it was merely edited — which has caused real failures before (an old invoice rejected by Sage 50's own cutoff rule, killing the whole run). Prefer Invoice date unless you specifically need this.
Invoice number rangeReference numbers between a Start and an End (both ends included)You know the numeric range of what's missing, e.g. "everything between RSRE_000090 and RSRE_000095."
Invoice number listAn explicit, exact list of reference numbers you type inYou know precisely which invoice(s) you need. Looks each one up individually rather than paging through PortPro's list — also why it's more reliable at finding an invoice the list view sometimes misses (see section 13).

Every mode except Continue is a one-time override for this run only — none of them read or change the saved "continue from" position.

Example — Invoice date. Goal: import everything invoiced in July 2026. Set Mode = Invoice date, From = 2026-07-01, To = 2026-07-31, then click Manual Run.

Example — Invoice number list. Goal: re-check three specific invoices that came back as failures last week. Set Mode = Invoice number list, and type: RSRE_000284, RSRE_000301, RSRE_000455 then click Manual Run.

Other fields on this tab

  • Cutoff (Lower) Invoice Date — a hard floor: no invoice dated before this date is ever processed, by Manual Run or the Automatic Service, no matter which Mode is used. Exists specifically to stop Sage 50's own "Do Not Allow Transactions Dated Before…" rule from rejecting an invoice mid-run and killing everything after it. Shared with the Automatic Sync tab, saves instantly.
  • Start invoice number / End invoice number — only used by Invoice number range mode. Leave either blank for "no bound in that direction."
  • Invoice number list — only used by Invoice number list mode. This box resizes itself as you resize the window (tracks about 75% of the window's width).
  • Override "Already Imported" check for this run — normally, an invoice this app already recorded as imported is silently skipped on every later run. Checking this box turns that skip off for this run only: a previously-imported invoice is re-validated and re-posted instead. Only available for Invoice date, Invoice number range, and Invoice number list modes.
    • Never saved anywhere — always starts unchecked, and resets itself the moment the run it applied to finishes or is stopped.
    • Shows an extra warning before the run starts, since a genuinely-still-present invoice would be posted twice if you're wrong. Only use this after confirming, in Sage 50 itself, that the invoice needs to go in again.
    • Any run that used it is marked "(Override)" everywhere its Mode is shown, so it's never ambiguous afterward.
  • Max invoices to process (0 = no limit) — caps how many genuinely processed invoices this run will actually handle. "Processed" means imported (or simulated, under Dry Run) or failed — an already-imported invoice does not count against this cap, since nothing was actually done for it.
  • Show command window while running — checked (default) pops up the Service's console window live; unchecked runs hidden in the background. Shared with Automatic Sync, saves instantly.
  • Dry run (Simulated - Default 10 Invoices and no real Sage 50 Changes) — the exact same setting as the Sage 50 tab's Dry run checkbox, editable here too; toggling it either place saves immediately and applies everywhere.
    • Checking it sets Max invoices to process to 10 automatically — keeps a test run quick by default. Unchecking it resets Max invoices back to 0, so a leftover test cap can't silently limit a real run.
    • A Dry Run invoice is never marked as imported, so the same range run for real afterward genuinely processes it.
    • Any run that used Dry Run is marked "(Dry Run)" everywhere its Mode is shown, and every count is relabeled as simulated.

Previous Run (read-only)

A snapshot of the most recently completed run — whether started from here, from Automatic Sync, or from a trigger file. Shows Mode (with "(Override)"/"(Dry Run)" appended if used), date/invoice range, Max invoices, the first and last invoice actually processed, a SUCCESS / FINISHED WITH ERRORS / INTERRUPTED result line (marked simulated for a Dry Run), and the exact invoice list used, when applicable.

Buttons

  • Manual Run — validates your inputs, warns about a possibly-conflicting Sage 50 session, shows a confirmation dialog, then starts it. Switches you to History & Logs automatically.
  • Stop Manual Run — sends a graceful shutdown signal first, force-kills only if it doesn't respond within 5 seconds.
  • Save — remembers your current field values for next time; also happens automatically the moment you click Manual Run.

5. Automatic Sync tab

Use this to configure and control the background service that runs continuously, watching for new/changed invoices on its own schedule.

Fields

  • Automatic Sync - Processing Delay (Days) — holds back the most recent N days before they're eligible to sync. A live readout shows exactly what date that resolves to. A rolling delay, not a permanent skip. 0 disables it.
  • Automatic Sync - Polling Interval (minutes) — how often the service checks PortPro on its own. (Manual trigger files are always picked up within about 15 seconds regardless.)
  • Cutoff (Lower) Invoice Date and Show command window while running — the same shared fields described under Manual Run; changing either here changes it everywhere.

Previous Run

Identical in content and layout to the Manual Run tab's Previous Run section.

Buttons

  • Save Automatic Sync settings — saves Polling Interval and Processing Delay.
  • Start Automatic Service — same pre-flight checks as Manual Run, shows a confirmation, then starts the long-running background process.
  • Stop Automatic Service — confirms, then gracefully stops it.

Settings changes need a restart. If the Automatic Service is already running and you change/Save a setting anywhere in the app, the running process keeps using the old values until you stop and restart it.

Full Customer Refresh tab

The third tab, right after Automatic Sync, for one specific job: pushing every PortPro customer's full profile (address, city, province, country, postal code, phone, email, contact, currency) onto its matching Sage 50 customer, on demand, right now — as opposed to the automatic "Update Customer with latest changes in PortPro" sweep (Sage 50 tab), which only ever touches a customer whose PortPro profile has changed since it was last synced. This tab ignores that changed-since-last-sync check entirely and refreshes every matching customer unconditionally.

This will overwrite Sage 50 customer data. Whatever PortPro currently has on file replaces whatever's in Sage 50 for that customer — any change made directly in Sage 50 to a customer's address, phone, email, etc. is lost. It only updates customers that already exist in Sage 50 by name; it never creates a new one (a missing customer is still only ever created automatically, the normal way, the first time an invoice needs it).

  • "FULL Customer profile refresh" checkbox — a confirmation gate, not a setting. Must be checked to enable the button below, and is never saved anywhere — always starts unchecked, and resets itself back to unchecked immediately after every click of the button, whatever the outcome.
  • Dry run (Simulated - Default 10 Customers and no real Sage 50 Changes) — a separate, independent Dry Run entirely its own - NOT the same setting as Manual Run / Sage 50 tab's Dry run, and toggling one never affects the other. Always defaults to checked when the app opens, and resets itself back to checked the moment a refresh finishes - succeeded, finished with errors, or interrupted.
    • Checking it sets Max customers to process to 10 automatically; unchecking it resets Max customers back to 0 (no limit).
  • Max customers to process (0 = no limit) — caps how many customers this refresh actually updates in Sage 50 (a customer not found in Sage 50 does not count against the cap). Never saved anywhere; resets to 10 the moment a refresh finishes.
  • Refresh FULL Customer button — shows a confirmation dialog titled "ALERT..!! (FULL Customer refresh)" summarizing write mode, max customers, and the company file, then starts the refresh in its own dedicated process, the same way Manual Run does. Disabled while the Automatic Service or a Manual Run is active (all three connect to Sage 50 under the same account).
  • Runs independently of Manual Run and the Automatic Service — it doesn't select invoices by date or number at all — but still registers its own row in History & Logs once finished, with Mode: "FULL Customer refresh" and Source: "Full Customer Refresh". The completion pop-up is also titled "ALERT..!! (FULL Customer refresh)".

6. Watermark tab

The "watermark" is the saved bookmark — a date plus an invoice number — that Continue mode and the Automatic Service's own polling both use to know where they left off. This tab lets you view it, and, if truly necessary, override it by hand.

Current Watermark (read-only)

Shows the watermark date and invoice number currently saved, with a Refresh button. Reads (none - no run has ever completed) if nothing has ever synced successfully yet.

Reset / Change Watermark

  • New Watermark Date — check the box and pick a date to set it explicitly; leave unchecked to clear the watermark entirely.
  • New Watermark Invoice # — reference/record-keeping only; the date is what actually controls fetching.

Both fields start out pre-filled with a copy of the current watermark.

This can move the watermark backward, not just forward. Doing so makes the next Continue run re-check invoices in the newly-covered range — but it will not create duplicates: every invoice already recorded as imported is still recognized and skipped. Only genuinely missed ones get imported.

Save button

Blocked entirely while any run is active. Shows a clear WARNING dialog comparing old and new values before committing — the old value is not recoverable once overwritten.

Click Refresh to reload from disk. The grid does not auto-refresh every couple of seconds anymore while something is running — only when you click Refresh, or once a run genuinely finishes.

Deleting a run (or runs)

Two ways to delete, both requiring confirmation first:

  • One row — click that row's Delete button.
  • Several rows at once — tick Select on each row you want gone (or click Select all, top-right), then click Delete Selected (also top-right, in red).

A run that's still actively in progress can't be deleted — you'll see a warning telling you to stop it first.

Deleting a run is permanent and removes everything it produced: its own request/result files, any failed-transaction CSV report, and its rows in the local tracking database — so those invoices are treated as brand new again the next time a real run touches them.

The detail tabs

  • Summary — full plain-text readout: request details, exact range/list used, every count, duration, watermark before/after.
  • Validate Invoice Extracted — one row per invoice this run touched: invoice #, PortPro date, success/fail, resulting Sage 50 invoice number, messages.
  • Invoice Transferred — one row per invoice actually written to Sage 50: PortPro #/date, Sage 50 #/date, due date, total amount, tax charged.
  • Warnings / Validation — just the warning/validation lines from this run's log.
  • Failed Transactions — just the error/failure lines.
  • Full log — the complete raw log text for this run, with a live search box.

Reading a gap-fill row

A "Finding the Gap" row is automatically created after almost every other run (see section 13). If you see one with "Fetched: 0/79" and "Not found: 79", that means it checked 79 candidates individually and genuinely didn't find any of them — a normal, healthy result, not an error.

8. PortPro tab

Connection settings for PortPro's API. You'll rarely need to touch most of these after initial setup:

  • Base URL / Invoice endpoint — where PortPro's API lives and where invoice data comes from.
  • Customer endpoint — the path used to fetch PortPro's full customer profile (address, billing email, contact, payment terms) — a separate, richer object than the lightweight caller info embedded on each invoice. Used when auto-creating a new Sage 50 customer, and by the periodic customer-update sync (see the Sage 50 tab).
  • Access token endpoint — reference/legacy; the real login flow uses New token endpoint instead.
  • New token endpoint — where a fresh access token is requested using the Refresh token, automatically, whenever the current one expires.
  • Page size — how many invoices PortPro returns per page (the app pages through everything automatically).
  • Timeout (seconds) — how long to wait for PortPro before giving up.
  • Access token / Refresh token (secrets) — your PortPro API credentials, refreshed automatically. Use Test Connection to confirm the currently saved credentials work.

Click Save PortPro settings to persist changes.

9. Sage 50 tab

Connection credentials and the account-mapping rules that decide exactly where each invoice line posts in Sage 50. This is the most consequential tab in the app — take the Dry run switch seriously.

  • App name / App ID — how this app identifies itself to the Sage 50 SDK.
  • Company data path — the full path to your .SAI company file. Use Test Connection to confirm it opens.
  • Sage50 User Name / Password — must be a dedicated account, never one a person also logs into interactively.
  • Expected SDK version — optional startup version check; leave blank to skip.
  • Default revenue account — the GL account used for a charge with no specific mapping below. If also blank, an unmapped charge fails outright.
  • Ignore account 1-on-1 match and apply default — checked: an unconfirmed mapped account just falls back to the default with a warning, instead of stopping the run.
  • Default receivable account — currently has no effect. Sage 50's customer object has no per-customer receivable-account property to write it to — Simply Accounting/Sage 50 posts every customer to one global AR control account, configured once in Sage 50 itself (Setup ▸ Settings ▸ Customers & Sales ▸ Linked Accounts). Kept in case a future SDK version adds support.
  • Default net payment terms (days) — the fallback "Net N days" term applied to an invoice when PortPro's own real per-invoice terms can't be used. PortPro normally supplies real terms directly, so this is a safety net, not the primary source. Example: 30.
  • Accounts To Trust — workaround for a known Sage 50 SDK quirk where a real, existing account is sometimes wrongly reported as missing. Only add an account here after confirming it's genuinely real in Sage 50.
  • Auto-create missing customers / items — checked: an unrecognized PortPro customer or charge item is created automatically before posting.
  • Update Customer with latest changes in PortPro — default checked. Once per Automatic Service cycle and once per Manual Run, checks every PortPro customer for a profile change since it was last synced, and pushes any change into the matching existing Sage 50 customer automatically. Does not affect creating brand new customers, which always happens with the full PortPro profile regardless of this setting.

    PortPro always wins. A manual correction made directly in Sage 50 (address, email, etc.) is overwritten the next time that customer's PortPro record changes.

  • Dry run — the most important switch on this screen. Checked: nothing is actually written to Sage 50, the run just logs what it would do. Always test something unfamiliar with this checked first. Also editable directly from the Manual Run tab (see section 4) - the exact same setting, in effect immediately either place.
  • Tax codes grid — maps a Canadian tax abbreviation (HST/GST/PST/QST) to the matching Sage 50 tax code.
  • Charge account map grid — maps each PortPro charge name to the Sage 50 GL account it should post to. Only Sage 50 Account Number actually affects posting.

Click Save Sage 50 settings to persist changes.

13. Understanding automatic gap-fill ("Finding the Gap")

This is the one behavior in the app that isn't a button you click — it just happens, automatically, after almost every run.

Why it exists

PortPro's normal invoice list — the one every date-range or number-range run uses — can, under certain conditions, silently leave out real invoices that genuinely exist. Looking that invoice up individually, by its exact reference number, finds it fine; it's specifically the bulk list view that can miss it. The app doesn't rely on you to remember to check — it checks automatically, every time.

How it works

After any range-based run finishes, the app automatically looks at the exact invoice-number range that run actually touched, figures out which numbers are not already recorded as imported, and looks each one up individually. This shows up in History & Logs as its own separate row, labeled "Finding the Gap". You never select this yourself.

Reading the result

Once a gap-fill row finishes, its Mode column shows something like:

Finding the Gap (19/98)

That means: 98 candidate invoice numbers were checked one by one, and 19 of them turned out to be real invoices that genuinely existed (and have now been imported). The other 79 were checked and confirmed to simply not exist — completely normal; invoice numbering in any system has gaps.

A gap-fill row with "0 found" is not a failure — it means the sweep found no genuinely missing invoices, the expected, healthy outcome most of the time.

14. Walkthroughs: common tasks step by step

Run a normal catch-up sync manually, right now

  1. Go to Manual Run.
  2. Set Mode to Continue.
  3. Click Manual Run, confirm the dialog.
  4. You'll land on History & Logs with the new run selected — watch Status until it says Completed.

Backfill a specific date range

  1. Go to Manual Run.
  2. Set Mode to Invoice date.
  3. Set Invoice Date From and Invoice Date To.
  4. Click Manual Run, confirm.
  5. A "Finding the Gap" follow-up row appears automatically underneath — let it finish too.

Re-check one or a few specific invoices you know the numbers of

  1. Go to Manual Run.
  2. Set Mode to Invoice number list.
  3. Type the reference numbers, comma-separated, e.g. RSRE_000284, RSRE_000301.
  4. Click Manual Run, confirm.

Test something unfamiliar before running it for real

  1. Go to Manual Run, check Dry run — Max invoices to process automatically becomes 10, so the test stays quick.
  2. Set up whatever you want to test (a new date range, a mode you don't usually use) and click Manual Run.
  3. Check History & Logs — the row shows "(Dry Run)" in Mode, and every count is labeled as simulated, so it's never mistaken for a real result.
  4. Uncheck Dry run (Max invoices resets to 0 automatically) and, if the test looked right, run it again for real.

Force-reprocess an invoice that's already marked as imported

Use this only after confirming, in Sage 50 itself, that the invoice genuinely needs to go in again.

  1. Go to Manual Run.
  2. Set Mode appropriately and enter the invoice(s).
  3. Check Override "Already Imported" check for this run.
  4. Click Manual Run — confirm the extra warning dialog only once you're sure.
  5. Confirm the normal run dialog too. The Mode will show "(Override)" afterward.

Figure out why a run had failures

  1. Go to History & Logs.
  2. Select the run (look for Failed validation/write > 0, or a non-Completed Status).
  3. Check Summary first for the overall counts.
  4. Check Failed Transactions for the specific error message(s).
  5. Use Full log and its search box for raw context.

Clean up an old test run from History & Logs

  1. Go to History & Logs.
  2. For one run: click Delete. For several: tick Select (or Select all), then Delete Selected.
  3. Confirm — permanently removes that run's files, reports, and tracking rows.

Confirm a setting change actually took effect

  1. Make your change, click that tab's Save button.
  2. Go to Automatic Sync, click Stop Automatic Service.
  3. Click Start Automatic Service again.
  4. (Optional) Check the confirmation dialog shown when starting — it summarizes the settings in effect.

An invoice needs to be re-imported after fixing an account mapping

  1. Fix the mapping on the Sage 50 tab, click Save Sage 50 settings.
  2. Go to Manual Run, Mode = Invoice number list, enter the reference number.
  3. Consider checking Dry run first to confirm the fix resolves it.

Something looks stuck — check what's actually running

  1. Look at the Process: line in the top bar.
  2. Use the top bar's Stop button if something genuinely needs stopping.

15. Troubleshooting / FAQ

I changed a setting and nothing seems different.

Did you click that tab's Save button? And if the Automatic Service was already running, did you restart it afterward?

The Manual Run / Start Automatic Service button is grayed out.

The other process is currently active — check the Process: line in the top bar. Stop it first.

A run shows "Interrupted (no result)" or "Interrupted (partial)".

The process stopped before finishing cleanly. Nothing already successfully imported is lost or will be double-imported; re-running the same range/Continue picks up exactly where it left off. Check Full log.

A "Finding the Gap" row found 0 invoices — is that a problem?

No — see section 13. That's the normal, healthy result most of the time.

An invoice was imported twice.

Shouldn't happen under normal operation. Check Validate Invoice Extracted for that invoice's Request ID(s), and see the Settings tab's Reset Imported-Invoice Tracking section (and whether "Override Already Imported check" was used).

I deleted a run from History & Logs by mistake — can I get it back?

No — deleting a run is permanent, by design. If the invoices it imported are still correctly in Sage 50, Sage 50 itself is unaffected — only this app's own history and bookkeeping.

Sage 50 says an account "doesn't exist" but I can see it in the chart of accounts.

A known Sage 50 SDK quirk — see Accounts To Trust on the Sage 50 tab.

Where do failed-transaction emails come from, and who gets them?

Configured on the Settings tab, under Email. If Enabled is unchecked, no email goes out, but a CSV report is still saved.

16. Glossary

  • Watermark — the saved bookmark (a date + invoice number) that Continue mode and the Automatic Service use to know where they left off.
  • Continue mode — the Mode option that resumes from the watermark automatically.
  • Gap-fill / "Finding the Gap" — the automatic follow-up sweep double-checking for invoices the bulk list view might have missed. See section 13.
  • Override Already Imported check — a Manual Run checkbox that lets a previously-imported invoice be re-processed for one run only. Never persisted; see section 4.
  • Dry run — a Sage 50 tab checkbox that simulates a run without writing anything real to Sage 50.
  • Trigger folder — the folder the running Service watches for new manual/trigger requests.
  • Request ID — the unique internal ID assigned to a single run, with a shorter "#" number for easier reference.
  • Cutoff (Lower) Invoice Date — the hard floor date below which no invoice is ever processed.
  • Processing Delay (Days) — how many of the most recent days are held back from automatic/Continue processing.
